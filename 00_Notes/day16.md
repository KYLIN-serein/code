## 📖 第一部分：复杂条件模拟（P1051 谁拿了最多奖学金）

**工程思维**：在真实的业务逻辑中，经常需要根据用户的各项指标（成绩、职位、论文）来综合计算奖励。这就要求我们对 `if-else` 的边界极其敏感。

### 1. 核心踩坑与解决
- **`%c` 读取的灾难**：题目输入是一行包含字符串、整数和字符（`Y`/`N`）。`scanf("%c", &ch)` 极易把上一行末尾的换行符 `\n` 当作有效字符吃掉，导致后续所有数据错位。
- **解药**：在 `%c` 前面强行加一个空格 `scanf(" %c", &ch);`，这个空格会强制跳掉所有的空白字符和换行符。

### 2. 核心代码逻辑
```c
// 累加计算每个人的奖金
int m = 0; 
if (qimo > 80 && lunwen >= 1) m += 8000;
if (qimo > 85 && lunwen >= 1) m += 4000;
if (qimo > 90) m += 2000;
if (qimo > 85 && banji > 80 && ganbu == 'Y') m += 850;
if (qimo > 85 && xibu == 'Y') m += 850;
// 注意：找最大奖金时，严格大于才更新，保证了“并列时输出最早出现的人”
```

## 📖 第二部分：多关键字二次排序（P1583 魔法照片）

**工程思维**：排序不是一劳永逸的。如果在第一轮排序后，数据发生改变（例如根据排名加了附加分），必须在修改后再次调用 `qsort` 进行二次排序。

### 1. 比较函数 `cmp` 的终极写法（防溢出 + 多关键字）
```c
int cmp(const void *a, const void *b) {
    struct person *p1 = (struct person *)a;
    struct person *p2 = (struct person *)b;

    // 第一关键字：权值降序（防溢出布尔写法）
    if (p1->w != p2->w) {
        return (p2->w > p1->w) - (p2->w < p1->w);
    } 
    // 第二关键字：编号升序（⚠️ 之前错写成了比较 w，必须比较 id！）
    else {
        return (p1->id > p2->id) - (p1->id < p2->id);
    }
}
```

### 2. 二次排序的下标魔法
```c
// 第一轮排序
qsort(p, n, sizeof(p[0]), cmp);

// 根据名次加上附加分 E
for (int i = 0; i < n; i++) {
    // (i + 1) 是第几名，比如第1名对应 E[1]，第10名对应 E[10]，第11名对应 E[1]
    p[i].w += E[(i + 1) % 10 == 0 ? 10 : (i + 1) % 10];
}

// 第二轮排序：权值变了，重新排！
qsort(p, n, sizeof(p[0]), cmp);
```

## 🧠 今日致命踩坑复盘（极其重要）

### 踩坑 1：`cmp` 里比错了变量
- **错误现象**：排出来的顺序完全不对。
- **原因**：当 `w` 相同的时候，直接用了 `p1->w - p2->w`（永远等于 0），忘记去比较 `id`。
- **纠正**：`if (p1->w != p2->w) { return 比 w; } else { return 比 id; }`。

### 踩坑 2：输出格式漏空格
- **错误现象**：输出结果长这样 `1345`，直接 WA。
- **原因**：`printf("%d", p[i].id);` 后面没有加空格。
- **纠正**：`printf("%d ", p[i].id);` 严格对齐题目要求的格式。
