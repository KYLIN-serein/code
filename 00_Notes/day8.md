## 📖 第一部分：C语言中的字符串与 `<string.h>`

**工程背景**：在 C 语言中，没有现成的 `String` 类型。所有的文本（姓名、密码、地址）都是以**字符数组**的形式存在的，且必须以隐藏的 `\0`（ASCII码为0）结尾。

### 1. 核心代码 (`employee_string.c`)
```c
#include <stdio.h>
#include <string.h> // 字符串工具箱

int main() {
    char name[20] = "张三";
    char dept[] = "_研发部";
    
    // strlen: 获取长度（遇到 \0 停止，不包含 \0 本身）
    printf("名字占用字符数: %d\n", (int)strlen(name));
    
    // strcat: 字符串拼接 (把 dept 拼到 name 后面)
    strcat(name, dept);
    printf("拼接后的结果: %s\n", name);
    
    return 0;
}
```

### 2. 工程硬核解析
- **预留空间**：`char name[20]` 申请了 20 字节，只用了 7 字节，剩下的是**预留空间**。做项目绝不能给得刚刚好，否则极易引发“内存溢出（Buffer Overflow）”漏洞。
- **`strcat` 的危险性**：它会找到 `name` 的末尾，把 `dept` 强行塞进去。如果 `name` 预留的空间不够大，它就会踩坏其他内存导致崩溃。企业级开发中，通常会用更安全的 `strncat` 来限制追加长度。

## 📖 第二部分：函数传参的底层真相——“地址传递”

**工程思维**：在 C 语言中，传参是“值传递”。但当我们处理庞大的数组时，复制整个数组极其浪费性能。C 语言给出的答案是：**传地址（指针）**。

### 1. 核心代码 (`employee_validate.c`)
```c
#include <stdio.h>

// 注意：这里的形参 int arr[] 本质就是一个指针（地址）
int calcTotalScore(int arr[], int len) {
    int sum = 0;
    for(int i = 0; i < len; i++) {
        sum += arr[i];
    }
    return sum;
}

int main() {
    int scores[3] = {80, 90, 100};
    
    // 核心：传数组名 scores，不需要加 &
    int total = calcTotalScore(scores, 3); 
    printf("总成绩: %d\n", total);
    
    return 0;
}
```

### 2. 硬核解析（极其重要）
- **为什么传数组名不加 `&`？** 因为**数组名本身就是一个地址**，它代表数组首元素的地址。
- **形参的伪装**：`int arr[]` 在函数参数列表中，会被编译器直接当成 `int *arr`（一个指针）来处理。它接收的是原数组在内存里的“门牌号”。
- **为什么还要传 `len`？** 函数拿到了首地址，却不知道这个数组到底有多长（不知道在哪停下），所以必须额外把长度传进去。

## 💻 第三部分：项目串联实战——“员工信息管理面板”

**工程需求**：将文本数据（姓名）和数字数据（分数）存入内存，并遍历输出，同时进行数据合法性校验。

### 1. 核心代码 (`employee_system.c`)
```c
#include <stdio.h>
#include <string.h>

int main() {
    // 1. 二维字符数组：存 3 个员工的名字，每个名字最长 20 字节
    char names[3][20] = {"张三", "李四", "王五"};
    
    // 2. 一维数组：存他们的分数
    int scores[3] = {88, 95, 76};
    
    printf("--- 员工数据面板 ---\n");
    
    // 3. 遍历输出
    for (int i = 0; i < 3; i++) {
        // 注意：names[i] 代表的正是第 i 行首字母的地址
        printf("员工姓名: %s, 绩效得分: %d\n", names[i], scores[i]);
        
        // 容错逻辑：校验名字长度
        if (strlen(names[i]) > 10) {
            printf("警告: 名字过长，可能存在异常！\n");
        }
    }
    return 0;
}
```

### 2. 工程硬核解析
- **二维字符数组底层**：`char names[3][20]` 申请了连续的 60 个字节，分成了 3 组（每组 20 个房间）。`names[0]` 对应第一组，`names[1]` 对应第二组。
- **`%s` 的魔法**：为什么打印用 `names[i]`？因为 `names[i]` 代表第 `i` 行首字母的**地址**。`%s` 收到地址后，会一直往后打印，直到遇到隐藏的 `\0` 为止。

## 🧠 今日踩坑与总结

1. **字符串比较的陷阱**：不能用 `==` 判断两个字符串内容是否相同（这会比较地址），必须用 `strcmp(a, b) == 0`。
2. **数组名就是指针**：深刻理解“数组名本身就是地址”这个概念，这是你后续学习纯指针、链表、甚至 C++ 引用传参的核心基石。
3. **安全防范思维**：处理字符串时，时刻警惕“空间够不够”，预防内存越界。
